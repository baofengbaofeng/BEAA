# iOS 本机安全与恢复

本轮提供源码和 XCTest 测试源码，没有执行 Apple 编译、模拟器、真机、Keychain 或生物识别验收。以下行为须由接手者在 Apple 环境验证。

## 存储边界

生产入口为 `SecureStateStore`，原 `StateFile` 仅用于旧格式迁移及测试。学习状态经过结构和业务校验后以 CryptoKit AES-GCM 加密；修订号参与认证附加数据。文件上限为 16 MiB。密钥、可信修订高水位和该修订密文摘要一起存入 Keychain，使用 `WhenUnlockedThisDeviceOnly`。服务名以稳定应用 bundle identifier 为基础，与状态文件路径无关。不要通过更换 bundle identifier 或删除 Keychain 项来“修复”额度。

保存由文件锁串行化。先原子写入带完整文件保护的加密 `.pending` 日志并同步文件及支持时的目录，再提交 Keychain 锚点，最后原子替换主文件。只有持久化成功，AppModel 才公开新状态及新资格。旧内存实例无法在高水位推进后覆盖新状态。

读取先验证主文件。主文件缺失、损坏或过旧时，只能使用与现有 Keychain 锚点的修订号和摘要完全相同、通过 AES-GCM 及状态校验的日志修复。现存坏主文件会先复制到带随机唯一名称的保护文件中。比锚点更新的日志绝不能推进高水位；锚点仍旧且主文件有效时，继续读取旧主文件。锚点已更新但主文件替换中断时，可恢复已经提交的精确状态，不会返还额度。

只有 Keychain 尚无锚点时，才接受现有明文 JSON 的首次受控迁移；原件会保留为受文件保护的唯一 `.legacy` 副本。首次密文先暂存，随后提交初始化锚点。一旦锚点存在，就不再把任何明文文件作为重新初始化理由。若主文件及匹配日志都丢失或无法验证，应用阻止使用及新资格，等待家长检查备份；绝不自动创建空账本。

这是应用级认证存储和防旧快照回放机制，不承诺抵抗已控制系统、提取密钥或任意修改 Keychain 的设备所有者。文件保护依赖设备解锁状态；旧明文归档仍是本机敏感数据，不能误当成加密备份。

## 加密备份

`BackupRecoveryView` 使用 FileDocument 及系统文件面板导出、选择、检查和恢复加密文件。操作入口检查当前家长授权；敏感页面由 ParentSessionView 在授权到期或离开应用时移除。

备份只能在仍保有相同 Keychain 密钥的本机恢复，不是跨设备迁移，也不是 iCloud 学习账本同步。低于当前高水位的备份会被拒绝。同修订必须匹配可信摘要，可以用最新有效备份修复坏文件，不会清空已用额度。没有本机密钥时不能解密，也不会宣称恢复成功。恢复前保留现有文件的唯一受保护副本。手动备份恢复需要家长授权；自动日志修复仅重建既有可信状态，两者均不能绕过密文认证、状态校验和修订限制。

## 家长凭据

六位数字 PIN 使用随机 16 字节盐及 PBKDF2-HMAC-SHA256，迭代 210,000 次，结果保存在本机 Keychain 中；不保存明文 PIN。连续错误五次暂停五分钟，失败状态持久保存。修改 PIN 需要当前 PIN 和两次一致的新 PIN。

家长通过现有 PIN 生成随机 128 位恢复码。界面仅本次显示原码，Keychain 仅保存 SHA-256 摘要。请离线保管，离开页面后无法再次显示。生成新码会使旧码失效。恢复码可以在忘记 PIN 时设置新 PIN，成功后立即作废；失败次数和五次错误后的五分钟冷却也持久保存。改 PIN 或用恢复码重设 PIN 都不会修改学习账本或增加额度。没有原 PIN、已保存的恢复码或此前开启的有效生物识别，应用不会临时注册一个新 PIN 来绕过坏账本。

生物识别默认关闭，须以当前 PIN 显式开启。独立 Keychain 标记受 `biometryCurrentSet` 保护，并绑定当前凭据哈希；PIN 改变会删除标记，设备生物识别登记变化会使标记不可用。验证使用仅生物识别的 LocalAuthentication 策略，不提供设备密码回退。设备中登记的人不自动等于家长；只在家长独占设备生物识别登记时开启。系统认证提示中的应用自定义中文附带拼音。

## 接手设置与验收

1. 使用稳定的应用 bundle identifier 和开发团队。确认应用包含 CryptoKit、Security、CommonCrypto、LocalAuthentication 相关源码，Info.plist 配置 Face ID 用途描述；无需向服务器上传凭据。
2. Apple 环境编译全部 target，并运行 `ParentVaultTests`、`SecurityRecoveryTests`、`SecureStorageTests`。这些测试使用注入的内存 Keychain 后端，不访问真实账户；生产默认后端始终是 Keychain。
3. 在测试设备首次设置 PIN，记录学习用时，改 PIN 后确认旧 PIN 无效、累计不变。生成恢复码，退出页面后以该码恢复 PIN；确认只能使用一次，并实测错误冷却。
4. 在真机显式开启生物识别，确认取消和失败不会授权、没有设备密码回退；更换登记或修改 PIN 后重新验证标记失效。确认应用后台及授权到期会移除安全页面。
5. 导出修订 A，增加用时后导出修订 B。恢复 A 必须拒绝；损坏主文件后重试读取应仅从匹配日志恢复 B，累计不降低。删除主文件和匹配日志后必须保持阻止使用，只有持有 B 且通过既有家长身份验证才可检查和恢复。
6. 模拟日志已暂存但锚点未更新：旧主文件仍可读取，新日志不能恢复或推进额度。模拟锚点已更新而主文件未替换：重试读取必须恢复匹配日志中的精确新状态，并保留旧主文件。
7. 在另一安装身份或丢失密钥的测试设备检查该备份，必须无法解密。不要用正式家庭数据测试删除 Keychain、重装或变更 bundle identifier；Keychain 是否跨卸载保留由系统决定，本实现不把卸载当作可用的安全恢复流程。

验收记录应分别列出静态源码检查、Xcode 编译、XCTest、系统认证和真机恢复结果，不把本轮源码交付写成已经通过真机安全验证。
