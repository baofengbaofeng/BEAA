# 跨平台剩余功能设计

用户要求解决剩余清单，并此前授权按判断开工。沿用现有 JS/TS/ArkTS/Swift 技术栈，分子系统实现；不会以 Node/结构检查替代设备、系统权限或教师验收。

1. 共享题型：保持 v1 单选兼容，新增显式 v2 混合题库与持久化答案校验，首次评分与订正分离，存储/备份/回执往返不丢字段。
2. 网页/鸿蒙离线对齐：新增分数及显式容差、历史错题与统计、等待挑战时的应急授权。云端跨平台采用可导出的明确数据边界，不伪造浏览器安全边界。
3. 鸿蒙原生：实现可测试的安全凭据/资格事务服务与平台端口，结合现有 RDB 和宿主生命周期；真实来源与限制动作使用明确能力门控，缺少正式权限时失败关闭。实际系统 API 以仓库预检/指定 SDK 为依据，不能发明普通应用权限。
4. iOS 迁移：独立于同机备份，家长显式导出、口令派生密钥加密和目标端确认；保留目标设备可信高水位，不覆盖或回退已有额度。导入不自动授权使用，需家长确认，并提供可解释的拒绝与恢复路径。
5. 课程：提供学科/年级/单元覆盖目录、分级练习包与机器校验、教师审核记录和发布门禁。未审核题不冒称教学认可。

候选方案比较：统一重写所有端成本大且破坏既有已测流程；仅更新清单不能解决功能；选择保持现有端口/协议的增量扩展与兼容迁移。该选择由实现方依据用户授权作出。

约束：全部应用中文提示配拼音；不清零原资格或旧记录；无私钥/真实凭据提交；Apple 编译测试用户后续执行；此前授权推送的是上一轮，不自动推送本轮。
